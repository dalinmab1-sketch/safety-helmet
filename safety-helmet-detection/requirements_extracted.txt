1. Project Overview
Safety Helmet Detection is a computer-vision application designed to identify whether people in a camera view are wearing required safety helmets. The system processes live or recorded video, detects people and helmets, associates helmets with people, and displays the detection result using bounding boxes, labels, confidence scores, and visual status indicators.
The project is intended as an educational and demonstration system for learning AI object detection, dataset preparation, model training, real-time inference, computer vision, and safety-monitoring workflows.
2. Project Goals
Detect people in a camera frame.
Detect whether each visible person's head is covered by a safety helmet.
Display Helmet / No Helmet status clearly.
Work with real-time webcam or CCTV-style video.
Provide confidence scores and visual bounding boxes.
Generate an alert when a person is detected without a helmet.
Maintain event statistics such as total people, helmet users, and violations.
Create a modular system that students can train, test, and improve.

5. AI Model Requirements
Use an object-detection model suitable for real-time inference.
YOLO-family models are recommended for the first implementation.
The model must be trained or fine-tuned on a helmet-safety dataset representative of the intended environment.
The dataset should include different helmet colors, lighting conditions, camera angles, distances, and partial occlusions.
Training and validation data must be separated to reduce data leakage.
The model should provide bounding boxes, class labels, and confidence scores.
Model version and training configuration should be documented.

For safety-related applications, the system should distinguish an uncertain detection from a confirmed violation. A low-confidence or heavily occluded case should be treated as Unknown rather than automatically classified as No Helmet.
13. Temporal Stability Requirements
Do not trigger a violation from a single low-confidence frame.
Require a configurable number of consistent detections or a time duration.
Use tracking where practical to reduce duplicate counting.
Use hysteresis or smoothing so the status does not rapidly switch between Helmet and No Helmet.
Reset the violation state when the person leaves the scene or the condition changes for a stable period.

17. Safety-Critical Usage Limitation
This project should initially be treated as a computer-vision demonstration and decision-support tool, not as the sole mechanism for enforcing workplace safety. Real-world deployment should include human review, site-specific validation, appropriate safety procedures, and testing under the actual operating conditions.
Do not assume 100% detection accuracy.
Do not automatically punish or identify a worker based solely on one AI prediction.
Provide an Unknown state for uncertain cases.
Validate the model on the actual environment before operational use.
Document model limitations and known failure cases.

24. Development Notes
The most important part of this project is not only detecting helmets but establishing a reliable relationship between a person and the helmet detection. The development team should therefore test both detection accuracy and person-helmet association accuracy.
For a student MVP, start with recorded images and video, then move to webcam inference. Once detection is stable, add temporal smoothing, alerts, statistics, and a dashboard. This staged approach makes debugging and evaluation easier.
